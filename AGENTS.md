# AGENTS.md — Birdy

Operational conventions for agents working in this repo. Read this first.

## Layout

- `pipeline/` — offline Python (uv-managed, `pipeline/.venv`): harvests xeno-canto,
  fits the physical syrinx model, trains the critic, builds the galaxy assets.
  Source: `pipeline/src/birdy_pipeline/`.
- `app/` — SvelteKit + TypeScript: realtime syrinx synth (AudioWorklet), mic analysis,
  Threlte 3D galaxy. Static assets generated by the pipeline live in `app/static/birdy/`.
  `inventory.json` there is the canonical whole-file checkpoint; `inventory/<id>.json`
  shards + `inventory/index.json` are the app's lazy view of it (pickers read the index,
  a bird's full entry loads on selection).
- `data/` — `inventory.json` (hand-authored, canonical), `learned-inventory.json`
  (generated by `learn`), `discovered-species.json`.
- `docs/` — the research base. **`docs/08-implementation.md` is normative**: both halves
  implement it. `docs/09` and `docs/10` are evidence records — read them before changing
  anything they measured.

## Hard constraints (violating these breaks the project)

- **No audio is ever retained or shipped — with one owner-sanctioned exception.**
  `harvest.py`'s decode → describe → delete loop remains the default and is
  load-bearing for licensing. Exception (owner decision, 2026-07-30): `sources fetch
  --keep-audio <dir>` may cache staged audio under `pipeline/out/audio-cache/` for
  the current training phase, so re-training doesn't re-download archives. The cache
  is local-only (`out/` is gitignored), feeds `harvest_directory` on re-runs, is
  never read by the app or copied into assets, and is **deleted when the training
  phase ends**. iNatSounds' own terms (no redistribution) are compatible with this;
  xeno-canto harvests still delete immediately.
- **Never delete `pipeline/out/harvest*` stores.** They are the only copies, gathered
  under xeno-canto rate limits.
- **No torch weights ship to the browser.** Assets are plain JSON/f32; the app must work
  with no Python process running.
- **The synthesiser stays physical and interpretable**; learned components analyse and
  score, they never generate audio.
- **Honesty rule (docs/08 §8.5):** every claim in the UI carries a confidence label;
  novel sounds are "unlabelled: real acoustics, no documented function".
- **Parity:** `app/scripts/verify-parity.mjs` must stay 14/14 and `render-syllable.mjs`
  44/44 after any synth-adjacent change.
- Evidence discipline: changes to fitting/objectives/spaces are judged by **pre-registered
  metrics** on a fixed store, and negative results are documented, not deleted (see
  docs/09 §9.7, docs/10 §10.5 for the pattern).

## Commands

All pipeline commands run from `pipeline/`:

```bash
uv run birdy-pipeline learn --store out/harvest-gan --critic out/critic.pt --embed-typing
uv run birdy-pipeline critic embed --store out/harvest-gan --critic out/critic.pt
uv run birdy-pipeline build --harvest-store out/harvest-gan \
     --inventory /home/sha5b/Documents/GitHub/Birdy/data/learned-inventory.json --space embed
uv run birdy-pipeline grow            # incremental: place newest audio, found novel knots
uv run birdy-pipeline placement       # score a fit on docs/09's four numbers
uv run birdy-pipeline docrefit ...    # one-tone documented re-fit (docs/16 §16.4)
uv run birdy-pipeline relations ...   # cross-species relations.json
uv run birdy-pipeline expand --dry-run  # novelty-guided harvest targets (no network)
uv run birdy-pipeline verify app/static/birdy
uv run birdy-pipeline serve           # Learn-tab control surface, loopback :8781
uv run birdy-pipeline sources list    # which audio sources are usable, and why not
uv run birdy-pipeline sources fetch --source internet-archive --limit 5 --store /tmp/...
uv run birdy-pipeline critic label-novel --store out/harvest-gan  # Perch 2.0 second opinions
```

Notes:

- `--inventory` paths are relative to CWD — use the absolute repo-root path for `data/`.
- `learn`/`build` run module self-tests at start; a failure there stops everything.
- A full `learn` on the 40 k/121-species store takes ~2–15 min (GPU); a full `build` ~7–9 min
  (~400 s of rendering). Run them as background tasks, never block on them.
- `learn` writes `<store>/typing.json` + `<store>/song-typing.json` (song-level types,
  docs/12) + `data/learned-inventory.json`;
  `critic embed` writes `<store>/embeddings.f32`; `build` writes `app/static/birdy/`.
  `auto` modes: `--space auto` → embed when embeddings exist; `--field-source auto` →
  syllable points when typing.json exists.
- Novelty recalibration after a big harvest: `critic.fit_novelty` on the current store
  (see docs/10 §10.3 — thresholds do not transfer across harvest epochs).
- `critic label-novel` (perch.py, optional `perch` extra = `onnxruntime` + the two hub
  packages — deliberately **no TensorFlow**) writes `<store>/perch-labels.jsonl`: Perch 2.0
  top-3 for every novelty-flagged syllable whose audio is still in `out/audio-cache/`
  (INAT* ids only; xeno-canto audio is deleted by design and is reported unlabelable).
  **These labels are metadata, never typing ground truth** (docs/13 §A1) — nothing in
  learn.py may read that file. The 409 MB ONNX port + class list download anonymously
  into `out/perch/` on first use (gitignored, local-only, same status as the audio cache).
- `learn --respiration` attaches the hand-set default respiratory set of docs/15 §1
  (`respiration.py`: air-sac oscillator replacing the envelope, √ps tract drive) to
  every fitted type. Off by default until the pre-registered per-species fit wins —
  the bake-off numbers are in docs/15 §1's status note.
- `learn --two-voice` attaches the hand-set default second voice of docs/15 §5
  (`twovoice.py`: the type's contour shifted by the Fig. 6 ratio, Table I's trachea,
  Laje & Mindlin coupling through the shared tracheal pressure) to every fitted
  type. Off by default until the pre-registered per-species fit wins — the bake-off
  numbers are in docs/15 §5's status note.
- The inversion gives flatness-heavy types (median member flatness ≥ 0.14, the
  harvest's p90) a **noise-first start** (docs/16 §16.7): `fricative: true` +
  formants seeded from the type's mel-envelope peaks, shipped on a type only where
  the resynthesis cosine beats the tonal fit. `fricative` routes turbulence around
  the f0-tracking band into the syllable's own formant set; syllables without it
  render bit-identically (parity fixtures `fricative`, `fricative+respiration`).
- **`serve` holds the pipeline in memory: restart it after every pipeline code change**,
  or its Learn-tab learn/build jobs run the code it started with (docs/11 §11.1 — this
  cost a galaxy once). It still defaults to the *old* `out/harvest` store, but a
  defaulted store is no longer silent: startup prints the store it is holding (path,
  syllables, species) and warns when a sibling store in `out/` has a newer
  `state.json` — read that line, or pass `--store out/harvest-gan` explicitly.
- Iterating on clustering? `build --dump-points /tmp/points.npz` writes the standardised
  matrix + labels once; experiment against that file, never re-render per idea.
- Iterating on the space map / per-session quality (docs/20)?
  `build --dump-spacemap-eval /tmp/eval.npz` writes the map's held-out rows with
  recording ids, the fit-side descriptor cloud, and the galaxy's centroids —
  one build, all the session analysis (single-clustering builds only).
- Debug builds that are not about the geometry battery should pass
  `--no-relations --no-compare-projections`: on the 56 k-point debug corpus a
  default build ran 33+ min at full CPU and timed out, with the relations
  permutation tests + all-projection comparison as the only skipped phases in
  the lean re-run (2026-07-31; the comparison timing is recorded in docs/20).
- **A type with member observations renders nothing since 2026-08-01** (W5 adopted): it
  already exists in the galaxy as the real syllables `typing.json` assigned to it.
  `--member-anchor` buys the rendered voice back (`--no-member-anchor` is gone). This
  halves the knot count, because a source split needs a point on both sides.
- **The per-cluster vectors are a binary sidecar**, `centroid-vectors.f32` — they were 64 %
  of centroids.json's bytes and it is parsed whole before the first frame. Read it with
  `galaxy.centroid_vectors` or `app/src/lib/data/centroid-vectors.ts`; never re-derive the
  layout, both accept the pre-2026-08-01 inline form. Contract: docs/08 §8.3.
- `build --clustering label` gives every typed point the knot of the type it already
  carries and fits kmeans only over the untyped remainder (docs/22 §22.8). It is the
  answer where `K_CAP` binds — production wants 27 862 clusters and keeps 8 192 — and
  worth +14 to +18 points of type retrieval there against +2.5 where the cap does not
  bind, so it is not the default. It also makes cluster purity and type coverage
  identities rather than measurements; read type retrieval instead.
- `build --clustering both` renders the corpus once and writes the kmeans map to
  `<out>/known` + the hdbscan map to `<out>/unknown` (each a complete, verifiable
  asset set) — the debug cycle's default, so the named and the discovery views of the
  same corpus are always comparable side by side.
- `sources` (sources.py) fetches from Zenodo, the Internet Archive, Kaggle (BirdCLEF)
  and Hugging Face (BirdSet) through the same decode → describe → delete loop as
  `harvest`. Keys live in `pipeline/.env` (template: `.env.example`: `XC_API_KEY`,
  `KAGGLE_USERNAME`/`KAGGLE_KEY`, `HF_TOKEN`, `ZENODO_TOKEN`); an unfilled key or a
  missing package is a logged skip with exit 0, never an error. The source SDKs are the
  optional `sources` extra in `pyproject.toml` (lazy imports, like the critic's torch) —
  do not `uv sync` it onto machines that only build the app.

App checks run from `app/`: `npm run check` (4 pre-existing errors in
`syrinx-processor.js` are known — no *new* errors allowed), `node scripts/verify-parity.mjs`.

## Verification discipline

- **Debug only, always (owner rule, 2026-07-31).** No production builds, no full
  harvests, no bulk network sweeps — everything is proven on **the 100-species debug
  subset** (`subset --species 100 --out /tmp/...` from the current big store, e.g.
  `/tmp/birdy-debug/harvest-100`), and production runs happen only when the owner
  explicitly calls for one, singularly, with the log read. This was restated after
  a production build OOM'd the machine; it overrides any earlier "production cycle"
  phrasing in HANDOFF.md.
- Verification runs go to `/tmp` (stores, assets, inventories). Never point a test
  `learn`/`build` at the real stores or `app/static/birdy/` — production runs are
  deliberate, singular, and their logs are read.
- `out/harvest-mp` (5 species, 1 562 syllables, no patches) is the fast loop for
  learn/build mechanics. Anything patch/embedding-related needs a subset of
  `out/harvest-gan` built via the `HarvestStore` API into `/tmp`.
- Report honest numbers, including the ones that hurt. A measurement that contradicts
  the plan is the deliverable, not a problem.

## Style

- Match the repo's docstring voice: dense, explains *why*, cites the measured numbers
  behind decisions. Refutations are recorded in place, not deleted.
- `docs/` prose (and the whitepaper) is written in STE-flavored Simplified Technical
  English (owner decision, 2026-08-01): short sentences (≤ ~25 words), active voice, one
  name for one thing, no semicolons in prose, no marketing adjectives. Keep new docs prose
  in that form; the full ruleset is the user's `ste-writing` skill.
- Minimal, scoped diffs; no drive-by refactors; no new dependencies without checking
  they're already in `pyproject.toml`/`package.json`.
- No `git commit/push` unless the user explicitly asks.

## One-off measurement runners

`pipeline/analysis/` holds the arms that were run once to settle a recorded question — W2's
held-out order scaling, W5's label/kmeans square, W6's Perch tests. Nothing imports them and
nothing ships them; they are in the repo because **each file's docstring is the
pre-registered gate of its run**, and a result whose gate cannot be re-read is not evidence.
`pipeline/analysis/README.md` maps file to question to verdict to the docs section.
